# Security Policy

## About This Project

Linux Digital Detective (LDD) is a defensive cybersecurity, digital forensics, and incident response project designed for authorized investigations and controlled security research.

The project processes Linux host evidence and sample security events to support investigation, detection, correlation, and reporting.

## Supported Versions

| Version | Supported |
|---|---|
| 1.0.x | Yes |
| < 1.0 | No |

## Reporting a Security Vulnerability

If you discover a security vulnerability in Linux Digital Detective, please report it privately rather than publicly disclosing it immediately.

When reporting a vulnerability, provide:

- A clear description of the issue
- The affected component or file
- Steps to reproduce the issue
- Expected and actual behavior
- Potential security impact
- Suggested remediation, if available

Please allow reasonable time for the issue to be reviewed before public disclosure.

## Do Not Include Sensitive Information

Do not submit the following through GitHub issues, pull requests, or public discussions:

- Passwords
- API keys
- Authentication tokens
- Private SSH keys
- Real credentials
- Production logs
- Confidential incident evidence
- Personally identifiable information
- Sensitive internal network information

Use sanitized or synthetic evidence when demonstrating security issues.

## Responsible Use

Linux Digital Detective is intended for:

- Digital forensics
- Incident response
- Defensive security research
- Security education
- Authorized laboratory environments
- Analysis of systems and evidence for which the investigator has permission

Do not use this project to access, monitor, compromise, or investigate systems without authorization.

## Evidence Privacy

Real forensic evidence may contain highly sensitive information.

Before sharing evidence with this project or publishing investigation results:

1. Remove credentials and secrets.
2. Remove personally identifiable information.
3. Sanitize internal hostnames and network information where appropriate.
4. Confirm that you have authorization to share the evidence.
5. Prefer synthetic or laboratory-generated evidence for public demonstrations.

## Security Updates

Security fixes may be released as new versions when appropriate.

Users are encouraged to keep the project updated and review release notes for security-related changes.
